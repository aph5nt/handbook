Replication: leader, leaderless, and lag

Postgres takes every write on one leader and streams its log to two followers. Cassandra lets any node take a write. Press Next to watch each one copy data, and the way each one loses a write.

Where you meet leader-follower

      
Postgres streaming replication and MySQL. A graph database cluster, with Raft to pick the leader. One node defines the order. You watch lag as a log position, and on failover you promote the follower with the highest position.

    

    

      
Where you meet leaderless

      
Cassandra and Riak, tuned by quorum. Any node takes a write, so a single node failure never stops writes. You choose how conflicts end: last-writer-wins, which can drop data, or version vectors, which keep both values for the app to merge.
