Checkpointer: save the state after every node

A checkpointer saves the graph's state after each node, under a thread id. A long investigation can then pause for a person, survive a crash, or be rewound. Watch a run crash and resume from its last checkpoint. Then switch tabs to see a checkpointer that lives only in memory.

Where you meet it

      
LangGraph checkpointers (in memory, SQLite, Postgres) keyed by thread_id, which also power interrupt and time travel. Temporal and other durable workflow engines do the same for any code.

    

    

      
The practical choice

      
Use a durable checkpointer (Postgres) in production and the in-memory one only in tests. Give every run a thread id. Make nodes safe to re-run, because a crash between a side effect and its checkpoint re-runs that node.
