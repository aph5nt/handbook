Where you meet it

      
PostgreSQL: top N per group with JOIN LATERAL and an index on (pool, ts). SQL Server calls the same idea CROSS APPLY and OUTER APPLY. A warehouse such as StarRocks writes it with ROW_NUMBER() in a CTE, filtered outside.

    

    

      
The practical choice

      
Few groups and a matching index: LATERAL, a short index read per group. Every group over the whole table, or no LATERAL in the engine: ROW_NUMBER() OVER (PARTITION BY pool ORDER BY ts DESC) <= 3, one scan. Use LEFT JOIN LATERAL ... ON true to keep groups with no rows.
