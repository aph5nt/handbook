Hooks: code that runs at fixed points of the loop

A hook is a script the harness runs at a fixed point: before a tool call, after it, when a prompt arrives, when the agent tries to stop. Its exit code can block the action. Watch a pre-tool hook refuse a command that would delete a database volume. Then switch tabs to see the same rule written in the prompt instead.

Where you meet it

      
Claude Code hooks (PreToolUse, PostToolUse, UserPromptSubmit, Stop) in settings.json. A safety hook that refuses destructive Docker or database commands. A Stop hook that refuses to finish until a required file exists.

    

    

      
The practical choice

      
Every rule that must hold goes into a hook, not the prompt: dangerous commands, protected paths, required checks before stopping. Return a clear reason so the agent can correct course. Keep the prompt for preferences, the hook for laws.
