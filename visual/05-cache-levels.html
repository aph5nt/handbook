Where you meet it

      
A graph database search that hits the page cache finishes in milliseconds. The same search cold, after a restart, reads every page from disk and takes many times longer. Warming the cache before taking traffic is the difference between a usable and an unusable node. In Go, a map guarded by a mutex in the process is the level above Redis, and it removes a network hop for the hottest keys.

    

    

      
The practical choice

      
Put a cache one level above where the cost is. Memory to network is about a thousand times, so a process cache in front of Redis wins big for hot keys. Redis in front of a database wins less in time, about ten times, but it is shared by every instance. Do not add a level without a reason for that gap.
