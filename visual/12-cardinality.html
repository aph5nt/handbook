Where you meet it

      
Every Prometheus metric in a serving stack, where a lane label has two values. Loki log lines that carry the address and the transaction hash instead. A series-count panel per job, so growth shows on the dashboard before memory runs out.

    

    

      
The practical choices

      
Review every new label like code: is its set of values small and fixed? Normalise paths to a pattern such as /address/{id}. Cap the series per metric in the store. Drop or rewrite an offending label at scrape time. Put user ids, addresses and request ids in logs and traces.
