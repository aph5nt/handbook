Where you meet it: a checkpoint table

      
A Go indexer writes rows to StarRocks and moves a checkpoint row. Each reader stores its own position. Kafka does the same with a consumer group offset. The practical choice: make every consumer idempotent, because a restart will read some rows again.

    

    

      
Where you meet it: the outbox and sagas

      
The outbox pattern writes the event in the same database transaction as the change, so the two never disagree. Choreography suits a few steps. When the flow needs a visible owner, use an orchestrator (a saga). Draw the flow: the code will not show it.
