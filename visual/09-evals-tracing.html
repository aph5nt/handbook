Evals, skills and tracing

A skill is packaged instructions kept in git. An eval proves it does its job: real failures become cases, runs go with and without the skill, code checks the hard rules and a judge checks the rest. Tracing records every model call and tool call of one request. Watch the eval loop. Then switch tabs to follow a slow answer through its trace.

Where you meet it

      
`claude plugin eval . --runs 3 --ablation with-without` for Claude Code skills. LangSmith, Langfuse and OpenTelemetry GenAI (generative AI) spans for tracing. A trace tree per request is how you find the one slow tool call among twenty.

    

    

      
The practical choice

      
Keep skills in git with an eval suite beside them. Grow cases from real wrong answers. Hard checks first, a judge second, several runs, and a with-and-without delta before a merge. Trace every request, and decide where the traces live before user prompts go into them.
