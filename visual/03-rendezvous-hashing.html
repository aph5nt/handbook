Rendezvous hashing

Five cache servers split wallet keys between them. Instead of a ring, each client scores every server for a key and picks the highest score. Press Next to watch the scores pick an owner, then watch server B leave.

Where you meet it

      
Memcached and Redis client libraries that pick a server for a key. Content delivery networks choosing which edge server keeps a file. A job queue split across a few workers, where a worker that joins takes only its own share of the jobs.

    

    

      
The choice you make

      
Use rendezvous hashing for tens of servers: it is short to write, even by default, and needs no virtual nodes. Use a ring with a sorted lookup for thousands of servers, where scoring every server per key costs too much.
