Row store or column store: which reads are cheap

The same table, stored two ways. A row store keeps each row together. A column store keeps each column in its own file. Watch what each one reads for one row by key, and for a total over a year. The last tab shows the mistake of feeding a column store one row at a time.

Where you meet it

      
An app keeps PostgreSQL, a row store, for orders and balances, and copies them out for reports. The indexer writes to StarRocks, a column store, in batches: one page of blocks per load. Lookups by address are served by the graph database, not the warehouse.

    

    

      
The practical choice

      
OLTP (Online Transaction Processing): many small reads and writes by key, so a row store. OLAP (Online Analytical Processing): few large scans over a few columns of many rows, so a column store. Copy data from one to the other. Never run one's work on the other.
