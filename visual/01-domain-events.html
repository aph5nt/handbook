Where you meet it

      
A Go indexer writes a block to StarRocks and records BlockIndexed in the same transaction. The graph sync reads that event and updates the graph a minute later. You show the gap as freshness: "graph is 1,200 blocks behind". With Kafka, the outbox is the table a relay (for example Debezium) reads and sends to the topic.

    

    

      
The practical choice

      
Name events in the past tense: WalletToppedUp, SwapDecoded. An event is history, not a request. Write it to an outbox in the same transaction. Make every consumer idempotent, because the relay may send it twice. If the business truly needs both changes at the same instant, they are one aggregate: redraw the border.
