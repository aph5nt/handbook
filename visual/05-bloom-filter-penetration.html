Cache penetration and Bloom filters

A script sends lookups for random addresses that do not exist. Each one is new, so it passes through the cache to the graph. Press Next and watch a row of sixteen bits answer "definitely not" without a database read.

Where you meet it

      
Public lookup APIs that bots probe with random keys. Inside databases: Cassandra, RocksDB and HBase keep a Bloom filter per file to skip files that cannot hold a key. Redis has the RedisBloom module.

    

    

      
The practical choice

      
Put a Bloom filter in front of lookups when misses for keys that do not exist are a real load. Size it for the false-positive rate you can afford. Add every key on write and rebuild it on a schedule.
