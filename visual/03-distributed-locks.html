Where you meet it

      
A Redis lock that stops two cron runs from sending the same daily email: an efficiency lock, Redis is fine. Leader election for an indexer that writes to a warehouse: a correctness lock, so use a Kubernetes lease or etcd. ZooKeeper's sequential ephemeral nodes are the classic fair lock.

    

    

      
The choice you make

      
First ask what happens if two workers hold the lock. If the answer is 'a little wasted work', a single Redis key with a timeout is enough. If the answer is 'data is corrupted', use a consensus store and make the storage check a growing token on every write.
