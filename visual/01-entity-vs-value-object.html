Entity and value object: who it is, or what it is

A shop has customers and order totals. Two customers can share a name and still be two people. Two amounts of 10 EUR are simply the same amount. Press Next and watch how each one changes, and what breaks when an amount is shared and changed in place.

Where you meet it

      
In a blockchain indexer, a liquidity pool is an entity: 10 ETH on Monday, 3 ETH on Friday, still pool 0xab... Money(amount, token), BlockRange(from, to) and DayPrice are values: two ranges from 100 to 200 are the same range. An address, a pool and a wallet are entities.

    

    

      
The practical choice

      
Default to a value object. Make it immutable and check it in its constructor, so it is born valid. Promote it to an entity only when you must follow it while it changes. A value that needs an entity holds the entity's id, never the entity itself.

Interview line"An entity has an identity that survives change. A value object is just its values, so I make it immutable: to change it, I make a new one."
