Where you meet it

      
Outside readers and reporting tools get SELECT on views, never on base tables. A view is also a stable contract: the base table can change its internals while the view's columns stay the same. In PostgreSQL, a view that filters rows for security is created WITH (security_barrier).

    

    

      
The practical choice

      
One layer: a view reads base tables only, never another view. A migration that touches a stacked view flattens it. Need speed instead of a door? That is a materialized view: a stored copy that needs its own grants and refreshes.
