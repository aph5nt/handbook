LSM tree versus B-tree

An indexer writes tens of thousands of rows a second. An LSM tree (log-structured merge tree) never updates a page in place. It writes to a log and a sorted table in memory, flushes sorted files, and merges them later. Watch writes, a read, compaction, and the stall.

Where you meet LSM trees

      
RocksDB, LevelDB, Cassandra and ScyllaDB. Pick one for write-heavy loads. A columnar warehouse such as StarRocks also writes new data as versions and compacts them in the background.

    

    

      
Where you meet B-trees

      
Postgres and MySQL InnoDB. One copy of each key, updated in place. Pick one for read-heavy loads with point updates. Watch for tombstones when an LSM table sees constant deletes.
