Map-reduce: the same prompt on every piece

Thirty incident notes from October need one monthly report. The same short prompt runs on each note in parallel (map). One last call combines the results (reduce). Watch the notes fan out and come back. Then switch tabs to see the reduce step overflow and drop the worst incident.

Where you meet it

      
Summarising a month of incident notes, many log files, or a long document split into parts. LangChain's map-reduce chain and many 'summarise this folder' features work this way. Anthropic's workflow patterns call it parallelization.

    

    

      
The practical choice

      
Make the map output a fixed small schema, so the reduce input stays small. Run the map calls in parallel and cap how many run at once. If the map outputs are still too many for one window, reduce in groups, then reduce the group results.
