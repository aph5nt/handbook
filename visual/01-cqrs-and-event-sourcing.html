Where you meet it

      
The chain, the warehouse and the graph are event sourcing and CQRS in the shape of the data, with no framework: blocks are the events, tables the write side, the graph the read side. Audit logs and money tracing use it because the history is the product.

    

    

      
The practical choice

      
Use CQRS when reads and writes want different shapes and the read model is the bottleneck. Use event sourcing when the history matters. For a plain create, read, update, delete (CRUD) screen, use neither: they double the code and add a lag for nothing.

Interview line"CQRS splits the model that takes commands from the model that answers questions. Event sourcing stores the events and folds them into any read model. I use them when reads differ from writes or the history is the product, and I design every reader for the lag."
