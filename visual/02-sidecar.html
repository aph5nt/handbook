Sidecar, ambassador and adapter

A Kubernetes pod runs the main container and helpers beside it, sharing its network and files. A sidecar adds a job such as shipping logs. An ambassador handles calls going out. An adapter reshapes what goes out. Press Next.

Where you meet it: logs and metrics

      
Log shippers (Fluent Bit, Promtail) and metric exporters run as sidecars or adapters, so every service gets them without code changes.

    

    

      
Where you meet it: meshes and local proxies

      
Envoy in Istio is an ambassador sidecar. A local MCP proxy beside an agent host plays the same role: the host calls localhost, the proxy handles the network, auth and metering.
