Where you meet it

      
Stripe and most payment APIs take an Idempotency-Key header and keep keys for about a day. A topup command in a CLI that retries on timeout. An indexer insert keyed by transaction hash and log index is idempotent by its natural key, so it needs no extra key.

    

    

      
The practical choices

      
The client makes the key, one per logical action, and reuses it on every retry. The server inserts the key first, in the same transaction as the effect, and stores the response. A repeat returns the stored response. A key with a different request body is refused. Keep keys longer than the longest retry window.
