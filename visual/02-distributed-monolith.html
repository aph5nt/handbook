Where you meet it: a split done by code, not by data

      
Teams often split the code into services and leave the database for later. Later never comes. Ask in any design review: which service owns this table, and who else reads it?

    

    

      
Where you meet it: the Tuesday test

      
Can one service deploy alone, on a normal Tuesday, with no meeting? If no, look for a shared table, a shared models library, or a synchronous chain. Each one forces lockstep.
