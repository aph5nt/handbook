Cache key design: the key decides what is shared

The risk service caches answers by address. Then it starts serving a second chain. Press Next and watch a key that is missing one input serve the wrong chain, and a key with extra parts never hit.

Where you meet it

      
Every Redis cache: a prefix per kind of answer lets you count, scan and drop one kind. HTTP caches build the key from the URL plus the headers named in Vary, by the same rule.

    

    

      
The practical choice

      
Build keys in one function. Include every input that changes the answer, normalised. Add a schema version to the prefix. Leave out request ids and timestamps. Test that equal requests give equal keys and different requests give different keys.
