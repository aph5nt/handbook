Locks and deadlocks: one lock order, or a cycle

A graph sync writes address nodes in page order: A, then B. A migration writes the same nodes in key order: B, then A. Watch each take its first lock and wait for the other. Then see the fix, one lock order, and the choice between optimistic and pessimistic writes.

Where you meet it

      
An indexer lane has one writer at a time. The lease is one statement: UPDATE lease SET owner = :me, epoch = epoch + 1 WHERE owner IS NULL OR expires < now(). Zero rows means someone else holds it. The epoch fences a stale writer that wakes up late.

    

    

      
The practical choice

      
Sort keys before writing, so every writer locks in the same order. Keep transactions small. A booking system with many fights for one seat locks first: SELECT ... FOR UPDATE. A profile edit that rarely conflicts uses a version column and retries.
