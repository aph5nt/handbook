Where you meet it

      
PostgreSQL defaults to read committed. Its repeatable read is snapshot isolation, which also stops phantoms. MySQL InnoDB defaults to repeatable read, and some phantoms still pass with locking reads. So say which engine before you say what a level means.

    

    

      
The practical choice

      
Most apps run read committed and make each rule one statement: UPDATE wallet SET balance = balance - 8 WHERE id = 7 AND balance >= 8. Where a rule spans rows, take a row lock with SELECT ... FOR UPDATE, or run serializable and retry on a serialization failure.
