Where you meet it

      
Every slow-query ticket: run EXPLAIN ANALYZE and paste the plan text into the issue. In a columnar warehouse such as StarRocks also read the bytes scanned per operator, not only rows. Typical finds: a full scan where an index was expected, 100 estimated against 3 million actual, a sort that spilled, a hash join whose build side is the big one.

    

    

      
The practical choice

      
Read from the leaves up and stop at the first operator that is wrong. If estimates are off, fix statistics or the predicate. If the shape flipped with data size, fix the shape: colocate, change the build side, or hint.
