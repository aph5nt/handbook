The inbox: remembering what was processed

The shipping service receives OrderPlaced events. A broker may deliver one twice. The shipping service keeps an inbox table of event ids it has processed. Press Next to see why the inbox row and the effect must share one transaction, and how long to keep the rows.

Where you meet it

      
Any at-least-once consumer whose effect is a database write: an inbox(message_id primary key) table next to the business tables. MassTransit, NServiceBus and Axon ship it built in.

    

    

      
When the effect is not in your database

      
Calling a courier or payment API cannot join your transaction. Pass the event id to the API as its idempotency key, so the remote side deduplicates for you.
