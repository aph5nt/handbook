Where you meet quorums

      
Cassandra and DynamoDB let you set W and R per query. N = 3, W = 2, R = 2 survives one dead node for both reads and writes. W = 1, R = 1 is fast and fine for a view counter, never for a balance.

    

    

      
Where you meet CAP

      
A graph database cluster with one leader refuses writes on the minority side of a split. That is CP. A DNS (Domain Name System) cache keeps answering old records. That is AP. The choice only exists while the network is split.
