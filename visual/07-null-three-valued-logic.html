NULL and three-valued logic: where rows vanish

A price column is NULL on days with no sealed price. A report filters WHERE price > 0. Watch two transfers disappear with no error. The second tab shows NOT IN returning nothing at all because of one NULL.

The code that runs this step


  


  

    TRUE: row kept
    UNKNOWN: a comparison with NULL
    FALSE or plain value
    lost with no error
    NULL: the value is unknown
  


  



      
Where you meet it

      
Price joins: a transfer on a day with no sealed price has a NULL price. A left join: the NULL on the right side is how you find rows with no partner. Data checks: COUNT(*) - COUNT(price) is the number of NULL prices.

    

    

      
The practical choice

      
Count the NULLs and show them, never filter them away by accident. Use IS NULL, IS DISTINCT FROM and COALESCE on purpose. Write NOT EXISTS, not NOT IN, when the list can hold a NULL.
