Hash map internals

A graph sync maps addresses to node ids. To keep the numbers readable, each address here is a short hex key, and its hash is simply its number: 0xa1 is 161. The bucket is the hash modulo the bucket count. Press Next to insert keys, fill the table, and watch it resize.

Where you meet a hash map

      
Go map[string]int from address to node id in a graph sync. Python dict. The visited set in a fund-tracing walk. Java HashMap resizes when the load factor passes 0.75, the same rule as here.

    

    

      
Where you meet it inside a database

      
A hash join builds this table on the small side of the join, keyed by the join column. Then it streams the big side and probes the table once per row. That is O(n + m), against O(n × m) for a nested loop.

Interview line"A hash map turns a key into a bucket number, so lookup is O(1) on average. Collisions are chained, and past a load factor of about 0.75 it doubles and rehashes, which is O(1) amortized."
