Repository and factory: valid at birth, saved whole

A new customer signs up. A factory, Wallet.open(owner), builds a wallet with a zero balance and a trial plan in one step. Later the application asks WalletRepository for it, changes it and saves it. It never writes SQL. Press Next.

Where you meet it

      
In a Go service, WalletRepository is an interface in the domain package. One adapter writes to StarRocks or Postgres, another is a map in memory, so tests run in milliseconds. In hexagonal architecture this is a port (chapter 2). An ORM (object-relational mapper) that generates one repository per table is the trap to watch for.

    

    

      
The practical choice

      
One repository per aggregate root, never per table. save writes the whole aggregate in one transaction. Make the constructor private, so the factory is the only way to get a wallet. A rule turned into an object, such as IsExchange.and(SeenInLast30Days), can be passed to the repository and pushed into the query when the data is big.
