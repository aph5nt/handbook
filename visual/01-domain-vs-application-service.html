Where you meet it

      
In Go or Rust: unexported fields, and methods that enforce the rule, so no other package can set the balance. A risk scorer that reads labels, flows and prices is a domain service. An HTTP handler or a Claude Code tool call is the application service: it parses input, calls the domain, saves, and returns. An ORM (object-relational mapper) pushes you to public setters. Push back.

    

    

      
The practical choice

      
Ask where the rule's data lives. One aggregate: the method goes on it. Several aggregates: a domain service. No rule, only steps: the application service. Test: can you unit test the rule with no database? Then it is in the domain. At a border (an API reply, a queue message) a plain data struct is right. Inside the domain it is a smell.
