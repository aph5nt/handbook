Visibility timeout

An SQS queue holds resize jobs. When a worker receives a job, SQS hides it from everyone else for 30 seconds. If the worker does not delete it in time, it comes back. Press Next to see that save a crashed job, then see a slow job run twice.

Where you meet it

      
Amazon SQS, Google Cloud Pub/Sub (acknowledgement deadline), Azure Service Bus (lock duration). RabbitMQ does the same through the open connection: an unacknowledged message returns when the consumer disconnects.

    

    

      
The practical choice

      
Set the visibility timeout longer than the slowest normal job. For jobs whose time varies, extend it while working with ChangeMessageVisibility. Make the handler idempotent anyway, and add a redrive policy so a job that keeps coming back ends in a DLQ.
