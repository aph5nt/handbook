Hexagonal architecture

A shop prices an order: 3 phones for 600 EUR, and orders over 500 EUR get 10 percent off. The rule lives in the core. The web, the command line, a test and two databases plug in around it. Press Next and swap the plugs.

The code that runs this step

Every line runs in handbook/code/02-hexagonal/main.go (go run .). The Postgres adapter prints its statement, so no database is needed. The lit lines are this step.

Where you meet it: a Go indexer

      
The core decodes blocks. It asks a BlockSource port for blocks and a RowSink port to write rows. In production a live chain node plugs in. In tests a sealed fixture file plugs in, and a throwaway StarRocks takes the rows. The core never changes for a test.

    

    

      
Where you meet it: an agent tool server

      
A local MCP (Model Context Protocol) proxy serves the same tools to Claude Code, Claude Desktop and a command line. Each host is a driving adapter. The cache and the remote graph are driven adapters. The practical choice: name each port in the business words, never SQLRepository.
