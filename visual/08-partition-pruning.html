Partition pruning: read 3 days, not 30

A warehouse table transfers is split into one partition per day of October 2026: 30 boxes. Inside each partition, every column is its own file: 12 columns. An analyst wants three days of totals. Watch the scanned bar.

Where you meet it

      
StarRocks and ClickHouse tables partitioned by day: an indexer writes into today's partition, and every report names a day range. BigQuery bills per byte scanned, so SELECT * on a terabyte table costs a terabyte. PostgreSQL range partitions prune the same way.

    

    

      
The practical choice

      
Name the partition column bare, with constants of the same type: day BETWEEN '2026-10-10' AND '2026-10-12'. Put the filter on the partitioned table itself, not only on a joined one. Name only the columns you need. Check the plan's partition count and scan bytes before you ship the query.
