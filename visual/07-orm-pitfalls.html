ORM pitfalls: the queries you cannot see

A dashboard's code is a simple loop over 100 pools. Under it, the ORM (Object-Relational Mapper) runs queries the code never shows. Watch each hidden cost appear in the database's query log. The second tab finds them in a test and fixes them.

Where you meet it

      
Django has select_related and prefetch_related. Rails has includes. Entity Framework has Include, and AsNoTracking for read-only queries. Hibernate has fetch joins. Every ORM lazy-loads by default somewhere.

    

    

      
The practical choice

      
Keep the ORM for simple create, read, update and delete. Write SQL by hand for reports and hot paths. Log the SQL in development, and put a query-count limit in the tests of every busy page.
