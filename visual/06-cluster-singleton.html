Cluster singleton: exactly one, on the oldest node

One maintenance scheduler books windows for every building, so two technicians are never sent to the same device. Two schedulers would double-book. It runs on the oldest node, and every node reaches it through a local proxy. Press Next to watch a handover, then the second tab: a partition with no split brain resolver.

Where you meet it

      
Akka and Akka.NET Cluster Singleton: schedulers, a leader that hands out work, and the shard coordinator of cluster sharding itself. Kubernetes leader election with a lease is the same idea outside actors.

    

    

      
The choice you make

      
Use it to coordinate, never to carry traffic: every message for it crosses to one node. Persist its state so the next one recovers it. Always run a split brain resolver, ideally keep oldest with down-if-alone.
