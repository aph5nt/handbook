Invariant: the rule that holds after every change

Where you meet it

      
A bank account that refuses an overdraft. A Kubernetes Deployment, whose replica count is never negative because the API server validates it. A Go indexer whose block aggregate refuses a receipt from another block: the block number must match. A Postgres CHECK constraint is the same idea one layer lower.

    

    

      
The practical choice

      
Write the invariant down in one sentence before you draw the aggregate. Check it in the root, after you compute the new state and before you save. If a rule needs data from two aggregates, decide on purpose: merge them, or accept a policy that corrects things later.
