Equality: identity versus value

Is this the same thing? An entity answers with its id. A value object answers with all its values. Get it wrong and a set keeps duplicates, or one pool becomes two. Press Next.

Where you meet it

      
Java and C# records, Kotlin data classes, Go structs and Rust #[derive(PartialEq, Eq, Hash)] give value equality from the fields. ORM entities (Hibernate, Entity Framework) compare by id. The indexer's BlockRange and Money are values; an address and a pool are entities.

    

    

      
The practical choice

      
Decide the kind first. Value object: immutable, equality and hash over every field. Entity: equality and hash over the id only, and the id never changes. Never use a mutable object as a map key.
