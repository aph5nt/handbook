Where you meet it

      
Indexer tables in StarRocks, a columnar warehouse, keep natural keys from the chain: a block height and a transaction hash never change. A user table in an app uses a surrogate id, because e-mail and name do change.

    

    

      
The practical choice

      
Pick the natural key when it is narrow and never changes. Otherwise add a surrogate key. A join-heavy warehouse may keep the 32-byte hash and add a narrow tx_id BIGINT beside it, so joins compare 8 bytes, not 32.
