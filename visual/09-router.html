Router: classify once, then run a fixed path

Questions reach a Chain Insights helper. A small model reads each one and picks one label from a fixed list. Code then runs the path for that label: an address search, an exchange lookup, or a docs search. Watch two questions take two paths. Then switch tabs to see a question that fits no path.

Where you meet it

      
Skill routing in an agent harness: a small model reads the prompt and picks one skill. A support bot that sends billing questions to one flow and technical questions to another. Model routing: easy questions to a cheap model, hard ones to a strong one.

    

    

      
The practical choice

      
Use the cheapest model that labels well, and a fixed list of labels as an enum. Put cheap code rules first: a 42-character 0x address needs no model. Add an 'unsure' label that asks back. Measure the router alone on labelled questions.
