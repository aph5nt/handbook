Where you meet it

      
A modular monolith with Go packages pricing, dex and transfers, each a candidate service later. A Java or C# solution split into projects per business area. A code review where a new package called utils or helpers appears: ask which business idea it serves.

    

    

      
The practical choice

      
Name every package with a business word. Keep each package's rule, tables and tests together. Export a small surface and keep the rest private. Split a context into modules first, and into services only when it must deploy alone.
