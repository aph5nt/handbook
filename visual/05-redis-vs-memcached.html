Where you meet it

      
Memcached: large plain caches of rendered pages or query results where many cores matter. Facebook ran it at huge scale. Redis: rate limits, sessions, leaderboards, queues, locks and invalidation messages.

    

    

      
The practical choice

      
Pick Redis unless you only need big plain values across many cores. Treat either one as a cache, not the system of record, unless you configure and test persistence. Ban KEYS and big DEL on shared Redis.

Interview line"Memcached is a multi-threaded plain key-value cache, Redis is a single-threaded data-structure server with persistence and publish-subscribe, so I pick Redis unless I only need big plain blobs across many cores."
