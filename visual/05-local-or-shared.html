Where you meet it

      
The Chain Insights proxy runs on each user's machine, so there is no shared cache. It keeps the exchange registry locally, refreshed from a public file, with the packaged copy as fallback. Memcached fits plain key-value with many threads. Redis adds data structures, persistence and publish-subscribe.

    

    

      
The practical choice

      
Local for the hottest 100 keys with a TTL of seconds. Shared Redis for the rest. When a user must see their own write, read that value from the shared cache, or route the user to one instance, or accept the window and say so.

    

  


  

    
Side by side

    

      
Local (in process)Shared (Redis)

      
SpeedNo network hopOne network hop

      
ViewOne copy per instanceOne view for all instances

      
RestartLost, starts coldSurvives a service restart

      
When it failsOnly that instanceEvery instance must fall back to the database

      
Interview line"Local is fastest but gives each instance its own view, shared gives one view at the cost of a hop, and most systems want both in layers."
