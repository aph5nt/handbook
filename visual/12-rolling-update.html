Rolling update: replace copies a few at a time

An MCP (Model Context Protocol) proxy runs as four copies in Kubernetes. A new version rolls out, one copy at a time, and capacity never drops. Then watch a bad version roll to every copy before anyone notices. Press Next.

Where you meet it

      
Kubernetes Deployments roll this way by default, with maxSurge and maxUnavailable in the rollout strategy. A worker pool that walks block ranges rolls one worker at a time, each finishing its range first. When two versions must never run together, use blue-green instead.

    

    

      
The practical choices

      
Set max unavailable to zero for a service that must keep its capacity. Gate every new copy on a readiness check. Pause after the first copy and compare its error rate with the old copies before going on. Keep the schema readable by both versions, because they serve together.
