Domain event versus integration event

A wallet top-up is news for two audiences: the subscription inside the same context, and other teams outside it. One event shape cannot serve both. Press Next.

Where you meet it

      
A Go indexer: BlockIndexed is internal to the indexer; the topic other teams read carries a small versioned schema in a schema registry. Kafka with Avro or Protobuf schemas and compatibility checks. Any public webhook: Stripe and GitHub version their event payloads.

    

    

      
The practical choice

      
Keep domain events private and free to change. Publish integration events through a translator, with a version in the name or the schema. Add fields freely, never rename or remove one in place: publish v2 beside v1 and retire v1 when nobody reads it.

Interview line"A domain event is private to its context and changes freely. An integration event is a published, versioned contract made by a translator. Publishing domain events raw turns every internal refactor into another team's outage."
