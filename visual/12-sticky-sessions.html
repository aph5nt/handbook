Sticky sessions: one client, always one copy

A proxy keeps each agent's session in memory. A sticky balancer pins every agent to the copy that holds its session. Watch it work, then watch the load go uneven and a restart log everyone out. Press Next.

Where you meet it

      
Cookie-based affinity in an L7 (application layer) balancer such as NGINX or an AWS ALB (Application Load Balancer). IP (Internet Protocol) hash affinity in an L4 balancer. WebSocket connections, which are sticky by nature and must be able to reconnect to any copy.

    

    

      
The practical choices

      
Move sessions to a shared store such as Redis, or into a signed token the client carries, and turn stickiness off. Keep affinity only as a cache-warmth hint that loses nothing when a client moves. Never pin by client IP when many users share one address.
