Immutable infrastructure: replace, never patch

Three indexer servers start the same. One team fixes them by hand for a year. Another builds one image per release, pins it by digest, and replaces copies instead of changing them. Watch which team can rebuild a dead server. Press Next.

Where you meet it

      
Lane values files that reference images by digest, never by tag. Kubernetes pods: a changed pod is a new pod, never an edited one. Terraform and golden machine images for virtual machines. Rollback is deploying the previous digest.

    

    

      
The practical choices

      
Build each release once, from a commit. Promote the same digest from test to staging to production. Never reference a mutable tag such as latest in a deploy. Never log in to fix a running server: change the code or config in git and replace the copy. Keep secrets and data outside the image.
