Materialized views: a saved result

A dashboard shows daily volume per DEX (decentralised exchange). Computing it from billions of swaps on every page load is slow. A materialized view, daily_dex_volume, stores the result. Watch it refresh, then open the second tab: staleness and refresh cost.

Where you meet it

      
StarRocks: an asynchronous materialized view refreshed per partition, and queries on the base table rewritten to read it. PostgreSQL: REFRESH MATERIALIZED VIEW CONCURRENTLY on a schedule, which needs a unique index on the view.

    

    

      
The practical choice

      
Refresh only the partitions that changed, usually today's. Show "data as of" on every dashboard that reads a view. Keep plain views for security, a read-only layer over base tables, and materialized views for speed.
