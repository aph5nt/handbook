Erlang OTP: gen_server and supervisors

In RabbitMQ, written in Erlang, every queue is one Erlang process built on OTP's gen_server. A client publishes with a call and waits for the reply. An acknowledgement is a cast. Press Next through call and cast, a supervisor restart, and the classic trap: one hot gen_server everyone calls.

Where you meet OTP

      
RabbitMQ, WhatsApp, Discord's chat backend in Elixir, telephone switches. OTP (Open Telecom Platform) gives gen_server, supervisors, gen_statem and applications. Akka's supervision tree is a copy of OTP's.

    

    

      
The choice you make

      
One process per key, never one process for everything: one per queue, per user, per device. Cast where no reply is needed. Set the restart intensity of each supervisor, so a crash loop escalates instead of spinning.
