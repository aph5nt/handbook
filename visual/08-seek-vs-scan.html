Where you meet it

      
WHERE tx_hash = :h on an indexed column is a seek. WHERE block_height BETWEEN 100 AND 200 is a range scan: one seek, then a short walk. A report that reads most of the table should scan: a million seeks cost more than one sweep.

    

    

      
The practical choice

      
Keep the column bare in the predicate. Move the function to the constant side, store the value already normalised, or build an index on the expression. Watch for an ORM that sends a string to an integer column: the cast lands on the column and the seek is gone.
