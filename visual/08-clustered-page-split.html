Clustered index and page splits: why random keys hurt

The orders table in MySQL InnoDB stores its rows inside the leaf pages of the primary key, four rows per page here. Watch where each new key lands.

Where you meet it

      
MySQL InnoDB and SQL Server: the primary key is the clustered key, so choose it for insert order. PostgreSQL stores a heap: CLUSTER reorders once, and new rows do not follow. StarRocks: the sort key is the column-store cousin.

    

    

      
The practical choice

      
Use a narrow, time-ordered key: a sequence, UUIDv7 or ULID. Keep a random UUID as a secondary unique column if the outside world needs one. Leave a fill factor below 100 where updates grow rows.
