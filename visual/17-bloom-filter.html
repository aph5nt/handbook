Bloom filter

Each data block of a warehouse table keeps a Bloom filter of the transaction hashes inside it. A query for one hash asks each filter first and opens only the blocks that answer maybe. Here is one filter: 16 bits and 3 hash functions.

Where you meet Bloom filters

      
RocksDB, Cassandra and other LSM (log-structured merge) stores keep one per data file, so a read skips files that cannot hold the key. Every Ethereum block header carries a 2,048-bit logs Bloom, so a log search skips blocks with no matching event.

    

    

      
The choices you make

      
Size it for the items you expect: about 10 bits per item and 7 hashes give roughly 1% false positives. Always confirm a maybe in the real data. To delete, use a counting Bloom filter.
