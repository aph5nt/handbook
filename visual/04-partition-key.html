Partition key

Every transfer event is published to a Kafka topic with three partitions. The key decides which partition it lands in, and so which events stay in order. Press Next to see one wallet's transfers stay together, three ways to choose a key badly, and what adding a partition does.

Where you meet it

      
Kafka's default partitioner hashes the key with murmur2 and takes it modulo the partition count. Kinesis and Pulsar do the same with a partition or shard key. SQS FIFO calls it the message group id.

    

    

      
The practical choice

      
Key by the entity whose events must stay in order: a wallet, an account, an order id. Check the busiest key's share of traffic. Pick the partition count early, with room to grow, because changing it moves keys.
