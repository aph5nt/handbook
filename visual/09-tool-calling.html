Tool calling: the model asks, your code runs

An investigator asks: "Who sent money to 0xabc on robinhood?" The model cannot touch the graph database. It writes a JSON (JavaScript Object Notation) request. The local MCP (Model Context Protocol) proxy checks it, runs it and hands the rows back. Watch each message cross the lanes. Then switch tabs to see a vague tool description send the model the wrong way.

Where you meet it

      
The Chain Insights proxy is an MCP server. Claude Desktop, Claude Code or an IDE (integrated development environment) lists its tools with no custom code. A refusal such as query_timeout comes back as a result with a reason, so the model can recover instead of guessing.

    

    

      
The practical choice

      
Write the description as a rule of use: "Use when you know an address and want its senders, never for a search by name." Put enums in the schema. Give names their own lookup tool, such as meta_dex_lookup, and say in the description that it comes first.
