Hedged requests: a second copy after the slow wait

An MCP (Model Context Protocol) proxy reads from one of two graph replicas. Most reads take 20 ms. One in a few hundred hits a replica in a pause and takes seconds. Watch a hedge cut that tail for a few percent extra load, then watch hedging everything double the load. Press Next.

Where you meet it

      
Google's tail-at-scale work: hedged reads in Bigtable and search back ends cut the slowest tail sharply for a few percent more load. Cassandra's speculative retry sends a second read after a percentile wait. Any read fan-out where one slow shard makes the whole page slow.

    

    

      
The practical choices

      
Hedge only reads and other idempotent calls. Wait for about the p95 time before sending the hedge, so only the slowest few percent get one. Cap hedges with a budget. Cancel the losing request. Send the hedge to a different replica, ideally in a different failure domain.
