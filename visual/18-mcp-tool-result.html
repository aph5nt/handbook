The tool result: a failure is not an error

The model sends a graph query with no anchor address. The server refuses it. How the server says no decides whether the model can recover. Press Next and compare a readable refusal with a protocol error.

Where you meet it

      
A graph proxy refuses an unanchored search with a result and isError: true. It sends rows as one text block and freshness as a second. List methods page with an opaque cursor. Stop sends notifications/cancelled, and the proxy kills the database statement.

    

    

      
The practical choice

      
Ask: can the model fix this by changing its call? If yes, return a result with isError: true and a reason written for the model. If the host or developer must fix it, return a JSON-RPC error.
