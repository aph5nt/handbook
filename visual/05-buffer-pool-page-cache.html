Buffer pool and the OS page cache

Postgres keeps hot pages in its buffer pool, and Linux keeps file pages in its page cache underneath. Press Next and follow page 7 from the disk into memory, twice. Then watch an oversized buffer pool starve the machine.

Where you meet it

      
Postgres shared_buffers and effective_cache_size, MySQL innodb_buffer_pool_size. DozerDB, like Neo4j, maps its store files into its own page cache, sized by setting. pg_prewarm refills the buffer pool after a restart.

    

    

      
The practical choice

      
Follow your database's sizing guide: about a quarter of RAM for Postgres shared buffers, most of the RAM for a database that uses direct I/O. Add an application cache only for answers that are costly to compute, not for raw pages.
