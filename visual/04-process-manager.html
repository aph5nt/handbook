Process manager

A top-up passes through wallet, units and receipt services. One process manager keeps a state for each top-up and decides the next step. Press Next to follow one top-up through its states, see a timeout turn into a compensation, and see two top-ups kept apart by correlation id.

Where you meet it

      
Temporal and Cadence workflows, AWS Step Functions, Camunda, NServiceBus and MassTransit sagas. Each stores the state per case durably, so a restart resumes where it stopped.

    

    

      
The practical choice

      
Draw the states first, with a timeout on every waiting state and a compensation for every step that changed something. Key every message by the case id. Make every handler idempotent, because messages may come twice.
