Cost and latency budgets

Every agent request has a budget: a number of tokens, a number of steps, and a time the user will wait. Five levers keep it inside: route easy work to a small model, cache the fixed prefix, cap the output, run independent calls in parallel, and stop at the cap. Watch a screening request pull each lever. Then switch tabs to see a request with no budget.

Where you meet it

      
A model router that sends classification to a small model and analysis to a large one. Prompt caching of a long system prompt and tool list. max_tokens on every call. Step caps in the agent executor. Per-tenant spend limits in an API (application programming interface) gateway.

    

    

      
The practical choice

      
Set a budget per request before you build: tokens, steps, seconds. Measure it with tracing. Route by difficulty, cache the stable prefix, cap the output, run independent calls in parallel, and stop at the cap with an honest partial answer.
