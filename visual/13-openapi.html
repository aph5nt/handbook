OpenAPI: the REST contract file

A transfers API has one file, openapi.yaml. Press Next and watch everything that comes from it: a mock server, a client library, request validation and a check in CI (Continuous Integration). Then see what happens when the server drifts from the file.

The code that runs this step

The lit lines are the ones the current step runs. The contract is a small Go value in the shape of an OpenAPI document, so the program needs only the standard library. Real tools read openapi.yaml the same way. Full program: handbook/code/13-openapi/main.go (go run .).

Where you meet it: public APIs

      
The file lives in the repository and is published as the docs page. A breaking-change linter runs on every pull request.

    

    

      
Where you meet it: front ends and SDKs

      
A front end starts against a mock server from the file. Typed clients in Go or TypeScript are generated instead of written by hand.
