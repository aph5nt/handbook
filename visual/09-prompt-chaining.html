Prompt chaining: small calls with a gate between

A daily incident report goes through three model calls: summarise, translate, format as a table. Between call 1 and call 2 a gate written in code checks that the summary names a risk level. Watch the output pass from step to step. Then switch tabs to see what one bad step does when no gate stands in the way.

Where you meet it

      
A release pipeline where one model call writes the changelog line and code does the rest. A daily report built as summarise, translate, format. LangChain calls the same thing a chain: prompt, model, output parser, next prompt.

    

    

      
The practical choice

      
Split a big prompt into small calls that each do one job, so each can be tested alone. Put a gate in code after any step whose output the next step trusts. Give the gate a retry cap, and send the reason back with the retry.
