Log compaction and tombstones

The topic token_metadata is keyed by contract address and holds each token's name and decimals. Nobody needs the old values, only the current one per token. Press Next to see compaction turn a log into a table, deletes travel as tombstones, and a lost pod restore its state.

Where you meet it

      
Kafka topics with cleanup.policy=compact: Kafka's own __consumer_offsets, Kafka Streams changelog topics, Kafka Connect configs, and lookup topics such as token metadata keyed by contract address.

    

    

      
The practical choice

      
Use compaction when consumers need the latest value per key and must be able to rebuild from zero. Keep a separate time-retained topic when anyone needs the history. Bring consumers back within delete.retention.ms, or rebuild them.
