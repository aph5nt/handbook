LSM tree and compaction: cheap writes, merged later

An indexer writes into a log-structured merge (LSM) store: a memtable in memory, then sorted files on three levels. StarRocks segments follow the same idea. Watch the file count.

Where you meet it

      
RocksDB, Cassandra and ScyllaDB are LSM stores. StarRocks and ClickHouse segments and parts follow the same flush-then-merge idea. Against a B-tree, an LSM store makes writes cheap appends and makes reads merge files.

    

    

      
The practical choice

      
Write in big batches, one load per table per page. Watch the file or version count per table. Give compaction threads before the writer outruns it.
