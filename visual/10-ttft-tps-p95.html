Where you meet it

      
A streaming chat or agent UI (user interface): TTFT (time to first token) is what the user feels first, so it gets the target. A batch job that writes reports cares about total tokens per hour, not TTFT. Load tests on vLLM or a hosted API show p95 TTFT rising first under overload.

    

    

      
The practical choice

      
Measure from the client side, under realistic peak load. Report TTFT and TPS (tokens per second) at p50 and p95, split by prompt size. When p95 TTFT is bad and TPS is steady, the fix is in the queue and the prompt, not the model.
