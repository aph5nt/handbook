Workflow versus agent

Every morning, 12 alerts from the night must become a one-page summary for the stand-up. Build it two ways. First as a workflow, where your code picks every step. Then as an agent, where the model picks. Watch the cost and the path, and see where each one breaks.

The code that runs this step

Where you meet a workflow

      
A release in a Claude Code harness: bump, build, test, tag, all in a script. One model call writes the changelog line. A skill router: a small model picks one skill, then a fixed path runs. Ordinary tests cover it, and the cost is known before it starts.

    

    

      
Where you meet an agent

      
Root-cause analysis of a red test or a strange alert. Nobody can write the path down, because each log decides the next step. You give it a step cap, a tool allow-list and a trace. When traces show the same three steps every time, those steps become a workflow.
