Memory and the context window

A long coding session fills the window with tool output. The harness summarises the oldest turns into a short note. A rule the operator gave in turn 3 is lost in that summary. The next day, a file-based memory brings the rule back. Watch the window on the left fill, shrink and refill. Then switch tabs to see the prompt cache break.

Where you meet it

      
A Claude Code memory folder: one fact per file and an index of one-line pointers. That is entity memory in plain files. Chat products keep a running summary plus the last few messages. Prompt caching rewards a prefix that stays the same, byte for byte, across calls.

    

    

      
The practical choice

      
Put rules in the system prompt or a skill, never only in a turn. Trim tool output before it enters the window. Keep timestamps and other changing text after the stable prefix. Save only the non-obvious: memory that repeats what the code already records is noise.
